# 城市集中供热 · 寒潮协同调度仿真与根因分析系统

在同一次寒潮气象过程下，仿真"热源能力—泵站压力—管网输运延迟—换热站—建筑热惯性—分区需求"
的联动过程，支持值守人员调度动作（热源出力、支路流量、临时限供），对异常给出
**可追溯的根因链**，并支持多种供热策略同气象对照运行、迟报气象数据到齐后的
**补算与重新评估**。

纯 Python 标准库实现，无任何第三方依赖。

## 运行

```bash
python3 -m heating_sim.cli                 # 终端演示：策略对照 + 根因链 + 迟报补算
python3 -m heating_sim.cli --json          # 结构化 JSON（指标/告警/根因链）
python3 -m heating_sim.cli --export-csv trace.csv
python3 -m unittest discover -s tests      # 15 个物理与业务测试
```

## 系统组成

| 模块 | 职责 |
| --- | --- |
| `heating_sim/model.py` | 数据模型：气象过程、调度动作 `Action`、逐分钟轨迹 `Trace`、告警、根因 |
| `heating_sim/network.py` | 泵站—并联支路水力联立；热媒微团输运（延迟 + 沿程温降）；快调压力暂态 |
| `heating_sim/zones.py` | 换热站取热（受负荷/流量/换热器能力约束）+ 建筑一阶 RC 热惯性 |
| `heating_sim/engine.py` | 联立推进；热源爬坡/装机约束、供水母管蓄能、回水管惯性；原始告警生成 |
| `heating_sim/diagnose.py` | 从告警出发沿动作记录与物理轨迹回溯因果链（根因，不只是告警） |
| `heating_sim/policies.py` | 策略接口与质调节气候补偿曲线 |
| `heating_sim/strategies/` | 四个对照策略（见下） |
| `heating_sim/weather.py` | 寒潮过程、迟报实测 `LateReport`、补算用气象源 `WeatherProvider` |
| `heating_sim/compare.py` | 同气象多策略对照、指标计算、迟报补算重评估 |
| `heating_sim/scenario.py` | 典型城市场景：1 热源 + 4 分区（医院/住宅/商业/开发园区） |

## 物理模型要点

- **输运延迟**：热源供水以"热媒微团"沿管道推进，按管长和当前流速决定渡越时间
  （近端医院约数分钟、远端园区约 1 小时），沿程按指数律温降；调节效果因此**延迟**到达。
- **水力耦合**：泵特性与各支路阻抗联立，`G_i = 开度_i·√(Δp/R_i)`；开大一条支路会
  挤占其他支路流量；阀门/限供单步大幅变化按导纳变化率产生**压力暂态**（关阀冲高、开阀掉压）。
- **换热站**：取热量追随分区热负荷（按设定室温 18℃ 计算），受流量与换热器能力约束；
  回水温度由 `tr = tin − Q/(m·cp)` 反推——流量过剩则回水升高（小温差/水力失衡），
  欠流则建筑降温、回水走低（大温差）。
- **建筑热惯性**：`C·dT/dt = Q − UA·(Tin−Tout)`，不同分区时间常数不同（住宅 30h、
  商业 12h、工业 8h），前期欠供会累积为后续持续低温。
- **热源**：出力有装机上限和爬坡速率；供水母管显式蓄能（能量守恒），
  峰值需求超过装机时供水温度抬不上去 → 全网欠供。

## 值守人员动作（`Action`）

```python
Action(minute=1200, source="人工/策略名",
       set_source_t_c=88.0)                 # 调热源供水目标温度
Action(minute=1200, source="...",
       set_source_w=30e6)                   # 或直接调热源出力
Action(minute=1200, source="...",
       branch_valve={"开发园区": 1.3})      # 调某条支路阀门开度
Action(minute=1200, source="...",
       curtail={"商业片区": 0.35},          # 临时削减非关键区域 35% 流量
       restore_after_min=180)               # 可自动恢复
```

## 四个对照策略（同一寒潮过程）

1. **气候补偿基线**：严格按预报气温的质调节曲线供水。
2. **提前蓄热保供**：寒潮前 8 小时前瞻逐步拉高供水，利用建筑惯性蓄热。
3. **激进快调（反面）**：一发现远端掉温就骤提供水并一次性全开阀门——
   复现压力波动、抢流量导致的回水偏高/水力失衡。
4. **峰值限供保关键**：热源逼近上限时渐进削减商业/园区流量，优先保医院和住宅。

## 根因而非告警

系统对每类异常沿"调度动作 → 水力/热力后果 → 建筑响应"回溯，给出因果链。例如：

- 压力波动 → 定位到是哪条支路在何时被一步开/关多少，说明是快速调节的直接物理后果；
- 回水偏高（小温差）→ 追溯到数小时前的抢流量式开阀（输运延迟使后果晚发）；
- 区域持续低温 → 区分"被临时限供（保关键的有意取舍）/ 热源顶装机 /
  热量还在管输途中 / 前期轻度欠供累积"；
- 回水偏低 → 区分"热源能力不足"与"供水温度—流量匹配不当"。

## 迟报数据补算

`WeatherProvider` 让每条实测报文带"实际收报时刻"：

```python
provider = WeatherProvider(forecast, [
    LateReport(12*60, 30*60, "tout_c", -25.5, received_minute=22*60,
               note="更强冷空气迟报")])
provider.known_at(20*60)        # 20h 时尚未收报，只能用预报
provider.fully_observed()       # 到齐后的修正气象 → 同一策略重跑即"补算重评估"
```

补算结果与原预报版运行逐指标对比，并重新生成告警与根因链（例如原运行未暴露的
热源顶上限、关键区低温会在补算后被重新识别）。仿真确定性可复现，便于复盘与审计。
